  Uvicorn vs FastAPI - The Relationship:

● FastAPI is the web framework (like Express.js for Node) - it defines routes, handles requests, validates data.

  Uvicorn is the ASGI server (like Node.js runtime itself) - it runs the FastAPI app, handles HTTP/WebSocket protocols.

  Why both are needed:
  - FastAPI = Your application code, routes, business logic
  - Uvicorn = Production server to run it (async, high-performance)

  Alternative stack: You could use gunicorn + uvicorn workers for production scaling, but for development and simple deployment, uvicorn alone is perfect.

  Benefits Uvicorn brings:
  - ✅ WebSocket support (essential for /sessions/{id}/stream)
  - ✅ Async/await performance for concurrent sessions
  - ✅ Production-ready HTTP/2, graceful shutdown
  - ✅ Hot reload during development

  FastAPI vs Uvicorn - Runtime Layers

  FastAPI alone (bare Python):

  # This works but is NOT production-ready
  from fastapi import FastAPI
  app = FastAPI()

  if __name__ == "__main__":
      import uvicorn
      uvicorn.run(app)  # Development only!

  Problems with bare Python:
  - ❌ Single-threaded - blocks on each request
  - ❌ No WebSocket support for real-time streaming
  - ❌ Poor performance under load
  - ❌ No graceful shutdown or process management

  Uvicorn (production web runtime):

  uvicorn semhost.main:create_app --factory --host 127.0.0.1 --port 7530

  What Uvicorn adds:
  - ✅ ASGI server - async/await, handles 1000s of concurrent connections
  - ✅ WebSocket support - essential for /sessions/{id}/stream
  - ✅ HTTP/2, keep-alive - modern web protocols
  - ✅ Process management - graceful shutdown, signal handling
  - ✅ Performance - ~10-50x faster than bare Python

  Think of it like:

  - FastAPI = Your web app code (like a React app)
  - Uvicorn = Production server (like Nginx for static files, but for Python ASGI)

  Alternative production servers:
  - gunicorn + uvicorn workers (for scaling across multiple CPU cores)
  - hypercorn (alternative ASGI server)

  But for ActCLI's use case, Uvicorn alone is perfect - it handles WebSockets, concurrent sessions, and performs excellently for localhost/small team deployments! 🚀
